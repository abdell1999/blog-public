Arquitectura de este blog

Cómo está construido este blog — Nuxt 4, Tailwind v4, Nuxt Content, sistema de temas, pipeline de contenido y deploy en GitHub Pages.

nuxtvuecontentdevopsmeta

Este artículo documenta cómo está construido el blog que estás leyendo. Lo escribo como referencia para mí mismo — para no tener que releer el código cada vez que quiera recordar cómo encajan las piezas — y como ejemplo real de un stack Nuxt 4 + Nuxt Content en producción.

Stack y arquitectura

El blog está construido con Nuxt 4, Tailwind CSS v4 (vía el plugin @tailwindcss/vite) y Nuxt Content v3 para el contenido en Markdown. El sistema de temas usa @nuxtjs/color-mode, y hay módulos adicionales para sitemap (@nuxtjs/sitemap) e imágenes Open Graph (nuxt-og-image).

La estructura de carpetas separa claramente tres responsabilidades:

  • app/ — páginas y componentes Vue (UI).
  • content/ — los posts y proyectos en Markdown, gestionados por Nuxt Content.
  • public/ — assets estáticos servidos tal cual (favicon, imágenes de posts).
  • server/routes/ — endpoints a medida, como el feed RSS.

El sitio no usa SSR en producción: el comando npm run generate prerenderiza todas las rutas a HTML estático, que es lo que GitHub Pages necesita (no ejecuta Node, solo sirve archivos).

Sistema de temas

El cambio de tema usa el módulo @nuxtjs/color-mode, configurado en nuxt.config.ts con preference: 'system', fallback: 'light' y classSuffix: '' (esto último hace que el <html> reciba directamente la clase light o dark, sin sufijo).

Los colores no están hardcodeados en los componentes: viven como variables CSS en app/assets/css/main.css, una vez para :root y otra vez para .dark:

:root {
  --bg: #ffffff;
  --fg: #111827;
  --bg-muted: #f3f4f6;
  --border: #e5e7eb;
  --accent: #4f46e5;
  --accent-fg: #ffffff;
}

.dark {
  --bg: #0f0f13;
  --fg: #f0f0f5;
  --bg-muted: #1a1a22;
  --border: #2a2a35;
  --accent: #818cf8;
  --accent-fg: #0f0f13;
}

Todos los componentes leen estas variables (var(--fg), var(--accent), etc.) en lugar de colores fijos, así que cambiar de tema no requiere tocar ningún componente.

El botón de cambio de tema (ThemeToggle) antes usaba emojis (💻☀️🌙) como iconos. Quedaban inconsistentes con el resto del sitio porque su render depende de la fuente de emoji del sistema operativo. Ahora usa SVG inline con stroke="currentColor", así que hereda exactamente el mismo color (var(--fg)) que el resto de la interfaz, en cualquier tema.

Pipeline de contenido

Cada post en content/posts/*.md pasa por el pipeline de Nuxt Content: el Markdown se parsea con remark/rehype a un AST, que además genera automáticamente un árbol de tabla de contenidos (post.body.toc.links) a partir de los h2/h3.

ArticleToc.vue usa ese árbol para renderizar la sidebar de navegación, y un IntersectionObserver para marcar como activo el heading visible en cada momento:

const observer = new IntersectionObserver(
  (entries) => {
    for (const entry of entries) {
      if (entry.isIntersecting) {
        activeId.value = entry.target.id
        break
      }
    }
  },
  { rootMargin: '-10% 0px -80% 0px', threshold: 0 },
)

Los bloques de código se renderizan con un componente Prose a medida, ProsePre.vue, que se ramifica en dos caminos según el lenguaje del bloque:

  • Si el lenguaje es mermaid, renderiza el diagrama en el cliente con mermaid.render() dentro de onMounted, y muestra un mensaje de carga mientras tanto.
  • Para cualquier otro lenguaje, muestra el bloque de código normal con un botón "Copiar" que solo aparece al hacer hover (patrón group / group-hover de Tailwind), usando navigator.clipboard.writeText().

RSS y deploy (CI/CD)

El feed RSS se genera en server/routes/rss.xml.ts, un endpoint de Nitro que usa la librería feed junto con queryCollection para leer los últimos 20 posts no-borrador, ordenados por fecha descendente, y devolver XML con el Content-Type correcto.

El deploy es totalmente automático vía GitHub Actions: cualquier push a main dispara .github/workflows/deploy.yml, que instala dependencias, corre npm run generate (usando las variables de entorno NUXT_APP_BASE_URL y NUXT_PUBLIC_SITE_URL definidas como repo vars), configura GitHub Pages con actions/configure-pages, sube el artefacto generado en .output/public y lo despliega.
